# Switching podcast audio from MP3 to M4A (AAC)

Date: 2026-09-20
Status: planning — not started
Spans: `news-radar` (this repo, generates the audio), `techradar` (consumer
site, one script), `podcast-app` (Android player — its side is detailed in
that repo's `docs/plans/2026-09-20-m4a-support.md`)

## Why

The `techradar` GitHub Pages site is over GitHub's documented 1 GB limit for
a published site. After the first retention run (2026-09-20) the Pages
artifact was still 2.23 GB, and almost all of it is audio: 179 mp3s ≈ 2.23 GB
(~12.5 MB each, 64 kbps mono 22.05 kHz). Retention at 90 days × 2 topics holds
the site at ~180 episodes, so it stabilises at ~2.2 GB — it never shrinks
below that. Deploys currently succeed (soft limit), but take 6–7 minutes
against a 10-minute deploy timeout.

MP3 at 32 kbps would halve the size but is audibly degraded on clean TTS
speech (swishy sibilants). AAC at 32 kbps is close to the current 64 kbps MP3
in quality at half the size. A/B clips were made on 2026-09-20 to confirm.

## Size math — m4a alone is not quite enough

| Setup | Steady-state audio |
|---|---|
| MP3 64k, 90 days (today) | ~2.2 GB |
| AAC 32k, 90 days | ~1.1 GB |
| AAC 32k, 75 days | ~0.95 GB |
| AAC 32k, 60 days | ~0.75 GB |

**Decision needed:** pair the format switch with a shorter audio retention
(recommended: 60 days, leaves headroom for HTML/JSON/covers and longer
episodes), or go lower on bitrate. The feed only lists the newest 20 episodes,
so shortening audio retention costs feed subscribers nothing. If 60 days
becomes the default, change `DEFAULT_AUDIO_MAX_AGE_DAYS` in
`newsradar/retention.py` (and the retention design doc).

## Hard constraint: do not re-encode the back catalog

`podcast-app` keys episodes on `audioUrl` (Room primary key), and the RSS
`<guid>` is the audio URL. Re-encoding existing episodes would change every
URL → duplicate episodes in every client, and lost heard state, positions,
likes and downloads in `podcast-app`.

So: **new episodes only**. Existing `.mp3` episodes stay as they are and age
out through retention. The site therefore shrinks gradually over the audio
retention window rather than on day one, and **every piece of code that looks
for audio must handle a mixed `.mp3` + `.m4a` catalog** during (and
harmlessly after) the transition.

## news-radar changes

### 1. Config: make the format selectable

Add `audio_format = "mp3" | "m4a"` (default `"mp3"`, so other consumers of
the package are unaffected) and an optional `audio_bitrate` (default `64k`
for mp3, `32k` for m4a). Parse in `config.py`; thread through `cli.py` to
`generate_podcast` and to the mp3-URL construction at `cli.py:455`.

### 2. `podcast_generator.py` — encode

- `_concat_wavs_to_mp3` (line 108) → `_concat_wavs_to_audio(wav_files, out_path, fmt, bitrate)`.
  For m4a: `-c:a aac -b:a 32k -ac 1 -movflags +faststart`. `+faststart` moves
  the moov atom to the front so the file streams over HTTP without a full
  download — required for the inline web player and for Cast.
- Keep `-ar 22050`? AAC-LC at 32 kbps mono is happier at 22.05–24 kHz than at
  44.1 kHz; TTS source is 24 kHz. Test both 22050 and 24000 and pick by ear.
- Output path at line 207 uses the configured extension.
- Open question: HE-AAC (`aac_at` via AudioToolbox on macOS, or `libfdk_aac`)
  sounds better than AAC-LC at ≤32 kbps, but stock ffmpeg's `aac` encoder is
  LC-only and `aac_at` ties the pipeline to macOS. Start with stock `aac`;
  only revisit if 32k LC isn't good enough.

### 3. `podcast_generator.py` — embedded chapters and cover

`_write_id3_chapters` (line 133) writes ID3v2 CHAP/CTOC/APIC with mutagen.
ID3 is MP3-only; mutagen's MP4 support cannot write chapters.

- **Chapters:** write an `FFMETADATA1` file with one `[CHAPTER]` block per
  chapter (`TIMEBASE=1/1000`, `START`, `END`, `title=`) and pass it to the
  encode with `-i meta.txt -map_metadata 1 -map_chapters 1`. This happens at
  encode time, so chapter timing must be known before the final encode — it
  already is (chapters are computed from WAV segment durations before
  `_write_id3_chapters` is called at line 346); the call order just needs
  rearranging for the m4a path.
- **Cover + title:** after encoding, `mutagen.mp4.MP4`: `©nam` for the title,
  `covr` with `MP4Cover(data, imageformat=MP4Cover.FORMAT_JPEG)`.
- Keep the ID3 path untouched for `audio_format = "mp3"`.
- The `.chapters.json` sidecar (Podcasting 2.0) is format-independent and
  needs no change. It is what Pocket Casts, Overcast, AntennaPod,
  `podcast-app` and our own web player use. Embedded chapters matter only for
  Apple Podcasts, which ignores `<podcast:chapters>`.

### 4. `podcast_rss.py` — mixed catalog

- Line 52 globs `**/{prefix}-*.mp3`. Glob both extensions, merge, sort by
  date, then cap at `MAX_EPISODES`. If a date somehow has both, prefer m4a.
- Line 65 / 97: per-episode URL uses the file's real extension; enclosure
  `type` is `audio/mpeg` for mp3, `audio/x-m4a` for m4a (Apple's recommended
  type; `audio/mp4` also works).
- Line 99 `<guid>`: unchanged behaviour (audio URL) — new episodes get new
  guids, old ones keep theirs.

### 5. `retention.py`

Add `".m4a"` to `_AUDIO_EXTS` (line 35). Keep `".mp3"`. Update the docstring
and the retention design doc's artifact list.

### 6. `html_generator.py`

`_podcast_player_html` (line 153) just emits `<audio src=…>`; AAC in MP4 plays
in every current browser. Only the parameter name (`mp3_url` → `audio_url`)
changes, through `cli.py:455–462`.

### 7. Tests

- `tests/test_podcast_rss.py`: mixed-catalog ordering, correct enclosure type
  per extension, 20-episode cap across both extensions.
- `tests/test_retention.py`: `.m4a` purged with the other audio artifacts.
- New: FFMETADATA chapter file generation (pure function — timebase, escaping
  of `=`, `;`, `#`, `\` and newlines in titles, which FFMETADATA requires).
- Encode smoke test gated on ffmpeg being present: produces a file,
  `ffprobe` reports N chapters and an attached cover.

## techradar changes

- `.github/scripts/generate-index.sh` line 175 finds the 🎙 badge target with
  `-name "*-radar-${date_part}.mp3"`. Match `.mp3` or `.m4a`.
- `config/config.toml`: set `audio_format = "m4a"` once everything below is
  verified. If audio retention is shortened, pass it via
  `retention-agent.sh` or rely on the new newsradar default.
- `retention.py` needs no change (extension list lives in newsradar).

## podcast-app changes

See `podcast-app/docs/plans/2026-09-20-m4a-support.md`. Summary: one required
fix (Cast hardcodes `audio/mpeg`), nothing else format-specific — the app
reads chapters from the JSON sidecar only and ExoPlayer sniffs the container.

## Rollout order

1. **podcast-app first** — ship the Cast MIME fix. It is backwards compatible,
   and the app must be ready before the first m4a episode appears.
2. **news-radar** — implement behind `audio_format`, default still mp3. Merge.
3. **techradar** — index script handles both extensions. Merge.
4. **One back-dated test episode** generated as m4a into a scratch output
   dir; run the verification list below.
5. Flip `audio_format = "m4a"` in `techradar/config/config.toml`.
6. Watch the Pages artifact size ("Final size is … bytes" in the deploy log)
   fall over the following weeks as mp3s age out.

## Verification before flipping the switch

- [ ] `ffprobe` shows chapters + cover on the m4a; moov atom is at the front.
- [ ] Web player on an episode page plays and seeks (Safari, Chrome, Firefox).
- [ ] Apple Podcasts: episode plays, **chapter list appears**, cover shows.
      This is the riskiest item — embedded chapters are a rewrite.
- [ ] Pocket Casts or Overcast: chapters via `<podcast:chapters>` still work.
- [ ] Feed validates (Cast Feed Validator / Podbase) with mixed enclosure types.
- [ ] podcast-app: stream, download, resume position, chapters, deep-dive.
- [ ] podcast-app: **Chromecast** plays an m4a episode.
- [ ] Retention dry run on a fixture containing `.m4a` files purges them.

## Rollback

Set `audio_format = "mp3"`. Already-published m4a episodes stay valid (mixed
catalog is supported permanently), so nothing needs to be regenerated.

## Out of scope

- Moving audio off GitHub Pages (R2/S3/Releases). Bigger win, bigger job;
  revisit if the site approaches 1 GB again after this change.
- Shrinking git history (~2.9 GB). Retention and m4a reduce the checkout and
  the Pages artifact, not the clone size.
